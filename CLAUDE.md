# CLAUDE.md - AI Assistant Guidelines

This file provides guidance for AI assistants working with this codebase.

## Repository Overview

Multi-language Bazel monorepo supporting Go and Python projects. Uses Bazel in **module mode** (bzlmod) with `MODULE.bazel`.

## Core Principles

### Hermetic Tooling

**All tools must be installed and managed by Bazel.** The only prerequisite is Bazelisk.

- Compilers, formatters, linters, code generators - everything comes from Bazel
- Never assume system-installed tools (no `go`, `python`, `shfmt` from PATH)
- Tool versions are pinned in `MODULE.bazel` or `tools/multitool.lock.json`

### Prebuilt Binaries for Smaller Tools

For faster repo setup, smaller tools are installed as prebuilt binaries via [rules_multitool](https://github.com/theoremlp/rules_multitool). See [tools/multitool.lock.json](tools/multitool.lock.json) for versions and checksums.

- Main tools (compilers, protoc): Use official Bazel rules (rules_go, rules_python)
- Smaller tools (shfmt, dprint, ruff, shellcheck): Download prebuilt binaries with SHA256 verification
- Platform support: macos/linux, arm64/x86_64

### VSCode Integration

Keep [.vscode/extensions.json](.vscode/extensions.json) and [.vscode/settings.json](.vscode/settings.json) in sync with Bazel-managed tools:

| Tool       | Bazel Source              | VSCode Extension          | VSCode Setting                    |
| ---------- | ------------------------- | ------------------------- | --------------------------------- |
| shfmt      | `@multitool//tools/shfmt` | `mkhl.shfmt`              | `shfmt.executablePath: bin/shfmt` |
| buildifier | `@buildifier_prebuilt`    | `bazelbuild.vscode-bazel` | `bazel.buildifierFixOnFormat`     |
| Go         | `@rules_go` (1.25)        | `golang.go`               | Uses devshell `bin/go`            |
| Python     | `@rules_python` (3.14)    | `ms-python.*`             | Uses `.venv` from devshell        |

When adding new tools:

1. Add to Bazel (MODULE.bazel or tools/multitool.lock.json)
2. Add wrapper to devshell.sh if needed for CLI use
3. Add VSCode extension to .vscode/extensions.json if applicable
4. Add VSCode settings to .vscode/settings.json to point to bin/ wrapper

## Project Structure

```
.
├── src/                    # Source code
│   ├── go/                 # Go packages
│   └── python/             # Python packages
├── tools/                  # Bazel tool definitions
│   └── multitool.lock.json # Prebuilt tool versions and checksums
├── bin/                    # Tool wrappers (generated by devshell.sh)
├── .vscode/                # VSCode configuration
├── MODULE.bazel            # Bazel module dependencies (bzlmod)
├── BUILD.bazel             # Root build file with format/gazelle targets
├── .bazelrc                # Bazel build settings
├── .editorconfig           # Editor formatting rules
└── devshell.sh             # Development environment setup
```

## Build System

### Bazel Commands

```bash
bazel build //...              # Build everything
bazel test //...               # Run all tests
bazel run //src/go/helloworld  # Run a target
```

### Formatting

Uses [aspect_rules_lint](https://github.com/aspect-build/rules_lint) for Bazel-native formatting with caching and RBE support.

```bash
bazel run //:format            # Format all files (Go, Python, Shell, Bazel, Markdown)
```

Formatters:

- **Go**: gofumpt (stricter gofmt)
- **Python**: ruff
- **Shell**: shfmt
- **Bazel files**: buildifier
- **Markdown**: dprint (fast Rust-based formatter)

### Linting

```bash
bazel run //:lint                # Lint all targets (Go, Python, Shell)
bazel run //:lint //src/...      # Lint specific package
```

Linters:

- **Go**: golangci-lint v2
- **Python**: ruff
- **Shell**: shellcheck

Linting runs via Bazel aspects on `*_library` and `*_binary` targets. Config files: [.golangci.yml](.golangci.yml), [.ruff.toml](.ruff.toml), [.shellcheckrc](.shellcheckrc).

### BUILD File Generation

```bash
bazel run //:gazelle           # Update BUILD files from source
```

### Python Dependencies

```bash
# After editing requirements.txt:
bazel run //:requirements.update  # Update lock file
bazel run //:gazelle              # Update BUILD files
```

## Development Environment

Run `./devshell.sh` to enter a shell with Bazel-managed tools in PATH. This:

1. Builds tools via Bazel
2. Creates wrappers in `bin/`
3. Sets up Python venv
4. Configures environment variables

## Code Style

Formatting is enforced via [.editorconfig](.editorconfig):

| File Type    | Indent   | Notes                            |
| ------------ | -------- | -------------------------------- |
| Default      | 2 spaces | LF line endings, UTF-8           |
| Shell (*.sh) | 2 spaces | Google style (shfmt flags)       |
| Go (*.go)    | Tabs     | Standard Go convention           |
| Bazel        | 4 spaces | *.bazel, *.bzl, BUILD, WORKSPACE |
| YAML/JSON    | 2 spaces |                                  |

## Adding New Languages/Tools

1. Add Bazel dependency to `MODULE.bazel`
2. Add formatter to `format_multirun` in root `BUILD.bazel` (see [aspect_rules_lint docs](https://github.com/aspect-build/rules_lint/blob/main/docs/formatting.md))
3. Update `devshell.sh` tools array if CLI access needed
4. Add VSCode extension to `.vscode/extensions.json`
5. Add VSCode settings to `.vscode/settings.json`
6. Update `.editorconfig` with language-specific rules
